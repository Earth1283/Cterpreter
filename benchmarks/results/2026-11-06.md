# 2026-11-06: a native compiler

Functions now compile to x86-64 machine code on their first call. Across all
twenty workloads the sum of medians falls from **7,239 ms to 518.5 ms, 92.8%
less time (13.96× faster)**; the eleven long kernels, where startup no longer
matters, run **14.68× faster** (6,820 → 465 ms). Cterpreter now beats CPython
3.14.4 on every workload, by 14.3× over the whole suite, and beats Node.js
26.10.0 on every workload, by 2.48× over the whole suite and by 1.05–4.4× on
the long kernels. These are results for this suite and machine, not a general
language speed ranking.

## Measurements

Baseline: commit `31a340c`, the tree before this pass (the same binary as the
`after` engine of the 2026-10-22 long-suite run). After: the working-tree
changes accompanying this report. Both were built from the same flags as a
CMake Release build (GCC 15.2.0, `-O3 -DNDEBUG`, C17, the project's warning
flags, no LTO or machine-specific flags) and were not rebuilt during the run.
Binary SHA-256 hashes are in the [raw results](2026-11-06.json).

Machine: AMD EPYC-Milan virtual machine, Linux x86-64, with the runner and every
child process pinned to CPU 0. Each engine received one untimed process per
workload, then 9 interleaved, shuffled timed runs; the tables report medians of
wall time including startup, parsing, compilation and output. Every timed output
was checked byte for byte against the host-compiled C program. Python and
Node.js ran the ports in `workloads.py` and `workloads.js`.

```sh
python3 benchmarks/run.py --engine before=BEFORE --engine after=AFTER \
  --suite all --repeats 9 --max-steps 100000000000 --timeout 600
```

The step limit lets `--jit auto` compile. Under the default limit of one
million steps nothing compiles and programs run exactly as before.

## Where the time went

- Compiled functions call each other directly, with arguments in registers, a
  pinned step budget, and a single stack comparison for the depth limit.
  Recursion into the same function is a relative call.
- Up to three integer and six `double` locals live in registers; constants
  are folded into immediates; division by a power of two is a shift.
- A memory access checks a per-site cache of the interpreter's object record.
  In a loop that calls nothing, arrays and unchanged pointers are validated once
  on entry and each element access becomes one bounds comparison.
- `ctype.h`, `abs`, `labs`, `sqrt` and `fabs` run inline, falling back to
  the library call for anything unusual.
- `printf`-family formatting now writes plain integer conversions itself and
  formats into a stack buffer, which also speeds up interpreted programs.

## Verification

All tests pass in Release and in AddressSanitizer + UndefinedBehaviorSanitizer
builds, both in the default mode and with `CTERPRETER_JIT=on` forcing every
interpreter to compile. The 2,100 differential cases against the baseline are
identical in output, diagnostics and status, including strict mode and step
limits of 1–40. `tests/jit_differential.py` compared interpreted and compiled
runs of over 15,000 generated programs, three quarters of which end in a
diagnostic, with no difference. About 2,600 random `printf`/`snprintf`
integer conversions print identically before and after.
