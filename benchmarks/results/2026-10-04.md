# 2026-10-04: arithmetic, conditions and call overhead

The nine-program suite takes **11.5% less wall time** after this pass (464.44 →
411.25 ms, a 1.13× speedup). Cterpreter wins seven of nine comparisons against
CPython 3.14.4. Python wins bubble sort by 1.5% and the string/ctype loop by
8.2%. These are results for this suite and machine, not a general language
speed ranking.

## Measurements

Baseline: commit `b56cba8`, freshly built before editing the source.
After: the working-tree changes accompanying this report. Both are CMake
Release builds with GCC 15.2.0, `-O3 -DNDEBUG`, C17, the same warning and
reproducibility flags, and no LTO or machine-specific flags. Neither binary
was rebuilt during measurement. Binary SHA-256 hashes are in the
[raw results](2026-10-04.json).

Machine: AMD EPYC-Milan virtual machine, Ubuntu 26.04, Linux x86-64. The runner
and every child process were pinned to CPU 0. No builds, tests or profilers
were run concurrently with this final timing pass. Each engine received one
untimed process per workload followed by 15 interleaved, shuffled timed runs.
The table reports medians, including startup, parsing and output. Every
timed output was checked byte for byte against the host-compiled C program.

| Workload | Before (ms) | After (ms) | Speedup | Python (ms) |
|---|---:|---:|---:|---:|
| Recursive `fib(29)` | 65.97 | 62.65 | 1.05× | 79.73 |
| 500,000 two-argument calls | 47.07 | 36.69 | 1.28× | 78.17 |
| 1,000,000 integer iterations | 82.02 | 60.72 | 1.35× | 116.91 |
| Sieve of 250,000 | 35.27 | 29.76 | 1.19× | 35.83 |
| Bubble sort of 900 ints | 47.91 | 46.50 | 1.03× | 45.82 |
| Matrix multiply, 48×48 | 15.66 | 15.03 | 1.04× | 30.98 |
| Mandelbrot, 160×120, 80 iterations | 69.60 | 65.97 | 1.06× | 75.27 |
| 400,000 switch transitions | 47.24 | 44.14 | 1.07× | 61.08 |
| 40,000 formatting/string/ctype iterations | 53.71 | 49.79 | 1.08× | 46.01 |
| **Sum of medians** | **464.44** | **411.25** | **1.13×** | **569.81** |

Python takes 1.39× as much time for the sum of medians. Startup contributes
substantially to short workloads such as matrix multiply; small differences,
including the bubble-sort race, should be treated cautiously on a shared VM.
The Python ports use the same loops, algorithms and checksums, with lists and
bytearrays representing the C arrays. Cterpreter also checks C-specific bounds,
initialization, lifetimes and arithmetic overflow. See the
[method and reproduction commands](../README.md).

## Changes

- Typed local `int` division, remainder and bitwise operations join the
  existing typed arithmetic handlers. Nested expressions whose operands are
  known ints or doubles use operator-specific handlers too. Runtime guards
  retain the general operator path, using already evaluated values so that
  side effects are never repeated.
- Stores and `+=`, `-=` and `*=` to local ints avoid generic scalar conversion
  and encoding when their values are ints. Mixed types keep the normal
  conversion rules, and failures leave the destination unwritten.
- Integer comparisons used by `if`, `for`, `while` and `do` produce truth
  directly. They keep the usual step/interrupt check and diagnostic fallback.
- Function declaration refines block scope requirements using established
  direct-call signatures. Scalar-returning calls need no aggregate temporary
  in their caller. Unknown calls, indirect callees and aggregate-producing
  arguments keep their scopes.
- Cached direct builtin calls reuse their known arity and resolved name.
  Definitions and pointer shadows are checked before evaluating arguments.
  Hot operand reads and builtin return handling stay inlined.

The guiding idea is small guarded specializations with inexpensive fallback,
as described in [CPython's PEP 659](https://peps.python.org/pep-0659/). Cterpreter
uses its existing AST dispatch rather than introducing a bytecode VM or JIT.

|---|---:|---:|---:|
| Integer loop | 950,027,236 | 770,017,570 | 18.9% |
| `fib(29)` | 838,796,237 | 779,727,820 | 7.0% |

For example, reproduce a count with:

```sh
valgrind --tool=callgrind --callgrind-out-file=build/callgrind.out \

callgrind_annotate build/callgrind.out
```

## Verification

- All 10 CTest checks pass in the Release build and in a Debug build with
  AddressSanitizer and UndefinedBehaviorSanitizer.
- Added arithmetic and core cases cover mixed stores, overflow, division by
  zero, uninitialized conditions, side effects, readonly objects, recursive
  frames, aggregate argument lifetimes, forward declarations, and cached
  builtin calls followed by user definitions or pointer shadows.
- The new regression assertions also pass against the baseline core library.
- 2,100 seeded differential programs produce identical stdout, stderr and
  exit status under the baseline and final binary, including strict mode and
  randomized low step/depth limits. The generator is checked into
  `tests/differential.py`.
- All nine Cterpreter and Python workloads match native C output on every
  warmup and timed run.
